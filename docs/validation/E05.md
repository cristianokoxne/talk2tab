# E05 — Seleção de contexto e catálogo de ações

## Resultado

O mapa enviado ao Jev agora prioriza candidatos com base no objetivo e no contexto semântico do controle, limita a lista a 60 escolhas por lote e o contexto serializado a 64 KiB. Quando há mais ações, a escolha `expand_candidates` carrega o lote seguinte sem interagir com a página. Valores internos de `<select>` permanecem locais; o Jev recebe identificadores opacos e rótulos legíveis.

## Critérios e evidências

- Ranking: 100 de 100 estados sintéticos apoiados mantiveram o controle relevante entre as opções.
- Limites: página sintética com 1.000 controles respeitou o limite de 60 opções e 64 KiB, reportando contexto omitido e ainda expondo o destino correspondente ao objetivo.
- Expansão: fixture com 140 controles recuperou um controle do segundo lote ao avançar o offset, sem executar uma ação de site para expandir.
- Privacidade do select: valor de opção sintético não aparece no JSON do mapa; o executor conserva o valor original localmente.
- Regressão: `npm run typecheck`, `npm run lint`, `npm test` (59 testes), `npm run test:e2e` (12 testes), `npm run bench:replay` (120 cenários catalogados) e `git diff --check` passaram.

## Limites conhecidos

O replay reporta os 120 cenários como catalogados; eles ainda não são todos executáveis. Os números de recall e orçamento vêm de fixtures sintéticas, não de uma medição de qualidade no serviço real do Jev. A validação de 1.000 controles cobre o limite de serialização, mas não representa uma página com 5.000 nós reais. O benchmark real de compreensão permanece para E06.
