# E10 — Navegação, abas e documentos restritos

## Resultado

Uma aba interna ou `about:blank` que não permite injeção agora gera um estado limitado, suficiente para o agente executar navegação HTTP(S) autorizada. URLs com esquemas executáveis/locais ou credenciais embutidas são recusadas. Ações de voltar/avançar usam o histórico da aba e a observação seguinte gera refs novos.

O alvo permanece na aba da sessão: a extensão deixou de sincronizar automaticamente com a aba ativa do usuário. Uma nova aba só é vinculada quando seu `openerTabId` corresponde ao alvo atual, ou quando a própria sessão pediu abrir/trocar de aba. Abas vinculadas recebem lock até o fim da sessão; abas criadas manualmente não transferem a tarefa. Fechar uma aba procura sucessora na mesma janela.

## Critérios e evidências

- De `chrome://newtab/`, o mapa continua a oferecer apenas a navegação HTTP(S) solicitada, sem exigir leitura da página interna.
- URLs HTTP(S) aceitas; `javascript:`, `data:`, `file:` e URLs com usuário/senha embutidos são bloqueadas.
- Regras de vínculo reconhecem apenas abas novas com `openerTabId` e ignoram abas abertas manualmente.
- Voltar e avançar são ações fechadas no mapa; redirecionamento/SPA são observados novamente na mesma aba.
- `npm run typecheck`, `npm run lint`, `npm test` (83 testes), `npm run test:e2e` (12 testes), `npm run bench:replay` e `git diff --check` passaram.

## Limites

O vínculo de `target=_blank` usa o evento de criação da aba e seu `openerTabId`; se um site abrir uma aba por uma rota sem vínculo de origem, o agente continua na aba original. Os testes de vínculo são unitários; a criação de nova aba é coberta pelo contrato da extensão, ainda sem fixture de integração com duas abas reais. A política de foco permanece fixa na aba de origem ou em um destino explicitamente escolhido pelo agente.
