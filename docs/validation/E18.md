# E18 — Diagnóstico, desempenho e intervenção

## Entrega

- O painel mostra os passos da sessão com tipo de ação, papel semântico e frame do alvo, efeito esperado, evidência, resultado observado, tempos de observação/mapa/Jev/espera, bytes do payload e quantidade de opções.
- A exportação gera JSON sanitizado, limitado a 50 passos. Rótulos, escolhas, modelos, papéis e códigos de erro usam allowlists; texto da página, valor digitado, URL, referência executável e mensagem livre de erro não entram no arquivo.
- O trace preserva fatos reportados pelo provider (modelo e confiança quando disponíveis), sem inferir raciocínio interno.
- O scanner consulta estilo e geometria apenas quando encontra uma faixa de rolagem, evitando trabalho de layout em elementos sem overflow.
- A medição de scanner roda no Chromium real via Playwright. O benchmark JSDOM foi descartado porque sua emulação de métricas de layout não representa o browser da extensão.
- Cache incremental permanece desabilitado; cada ação usa uma observação nova e a correção de referências é coberta por testes de interação.

## Evidências

Ambiente local medido em 2026-10-09: Windows 11 (10.0.26200), AMD Ryzen 7 8845HS, 16 processadores lógicos, Node v24.21.0, Chromium 156.0.8078.4.

Fixture: exatamente 5.000 elementos DOM, 10 varreduras de aquecimento e 30 medições. Scanner p50 189,8 ms, p95 207,2 ms, máximo 209,3 ms. Command map: 9,98 ms; 2 opções; payload 3.935 bytes (limite de 65.536 bytes e 60 opções). O budget inicial de p95 200 ms foi ajustado para 220 ms com base nessa medição.

- `npm run typecheck` — passou.
- `npm run lint` — passou.
- `npm test` — 126 testes passaram antes do ajuste de ordem no scanner.
- `npm run test:e2e` — 22 testes passaram antes do ajuste de ordem no scanner.
- `npm run bench:replay` — 120 cenários catalogados em 24 famílias.
- `npm run bench:scanner` — 30 medições concluídas; p95 dentro do budget ajustado de 220 ms.
- Testes de exportação com canários verificam a ausência de conteúdo privado e referências arbitrárias; o buffer do trace é limitado a 50 passos e a rolagem contínua existente limita o histórico a 100 entradas e aceita cancelamento.
- Reobservação de referências stale e nova decisão antes do próximo despacho são verificadas pelo teste do loop; o usuário pode intervir e a tarefa continua a partir da observação atual.

## Limitações

`traceBytes` mede o tamanho serializado do diagnóstico, não heap real da aba nem do worker. A retenção é limitada a 50 passos, e a medição do command map é uma amostra; novas fixtures podem ser adicionadas quando surgir evidência de gargalo. A validação com credential real do Jev não é necessária para estes budgets locais e não foi usada.
